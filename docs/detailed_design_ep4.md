# Epic 4 詳細設計：空き判定と予約の整合性

更新日：2026-09-29  
要件とロードマップ：[README](../README.md)  
実装範囲：Story 4.1／Task 4.1.1〜4.1.4

## 1. 共通計算（Task 4.1.1）

`src/lib/booking/availability-core.ts` の `calculateTotals` を検索と保存時の再判定で共用する。メニュー1件と重複のないオプションID群をDBから取り直し、有効状態を確認する。各メニュー時間は1〜1,380分、オプション時間は0〜1,380分、各料金は税込0〜1,000,000円。合計時間は1〜1,380分、税込合計料金は0〜1,000,000円とする。合計値に税を再加算しない。上限超過は拒否する。

必要枠数は `ceil(合計施術時間 / 60)`、施術終了は開始＋実分数、占有終了は開始＋必要枠数×60分。開始時刻と各占有枠は正時。日時はAsia/Tokyoの業務日をUTC時点へ変換し、終了を正時へ丸めるのは占有時間だけとする。選択内容を保存する際は同じサーバー側の計算値を使い、利用者から送られた合計・割当は採用しない。

## 2. 空き検索と保存直前の再判定（Task 4.1.2）

公開 `GET /api/availability?date=YYYY-MM-DD&treatmentId=UUID&optionId=UUID...` は、合計と予約可能な開始・施術終了・占有終了の一覧を返す。部屋・施術者IDは公開応答に含めない。`Cache-Control: no-store`。日付・UUID・オプション重複・未知のクエリ項目を検証する。

`findAvailability` はRepeatable Readトランザクション内で、対象日と前暦日の有効営業設定、当日有効な曜日別休憩、有効なメニュー・オプション・資源、当日の既存予約と施術中の終了超過を読む。対象日が休業日・設定なし、前日の閉店設定なし、受付期間外、資源なしなら候補は空。受付は30日前00:00から前暦日の設定閉店時刻までで、両端を含む。前日が休業日でも締切日を繰り上げない。

候補は開店時刻から閉店前まで1時間ごと。施術・占有が閉店までに終わり、同じ有効な部屋・施術者が全枠を通じて空き、施術者の休憩が対象曜日に設定済みで占有区間と重ならない場合だけ採用する。区間は開始を含み終了を含まない。既存のCONFIRMED・IN_PROGRESS・COMPLETED予約の占有区間で判定し、CANCELLEDは除外する。予定占有終了を過ぎたIN_PROGRESSの資源は、完了まで候補から除外する。

`revalidateAtSave(tx, input, startsAt, now)` は同一判定を保存トランザクション内で再実行する入口。現在時刻、選択マスタ、設定、資源、既存予約、割当を再取得し、候補が消えていれば保存側は競合として拒否する。Story 4.2の登録・変更処理はこの関数を呼んだうえ、予約本体・全ReservationSlotを同一トランザクションで書き込み、一意制約違反を競合として扱う。設定変更・退会との排他制御、二重送信、実際の保存APIへの接続はStory 4.2で実装する。検索応答自体は枠の確保を意味しない。

## 3. 割当優先順位（Task 4.1.3）

対象日の予約のうち、候補開始に占有終了が接するもの、または候補占有終了に開始が接するものを施術者ごとに数える。少ない候補を優先する。同数なら当日の既存予約の占有時間合計が少ない候補、さらに同数なら `createdAt`、IDの昇順。部屋も `createdAt`、IDの昇順。連続施術しか空きがなくても候補からは除かない。固定順は既存の資源レコードの作成順を使うため、名称変更で割当順位は変わらない。
